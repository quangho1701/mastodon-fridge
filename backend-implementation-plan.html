Backend Implementation Plan

High-level phase overview only. The granular planning — exact files, SQL, code shape — happens at build time with the model's thinking against the live repo. Total: ~19 working days for one focused developer.

7 phases Expo + Supabase 50-user closed beta

How to use this

Walk phases in order. When you reach a phase, hand the model the goal and ask it to plan and implement against the current codebase. This document deliberately does not prescribe steps, files, or SQL ahead of time — those decisions are better made with live context.

Reference final-decision.html for the binding architectural decisions. This document is the order in which to apply them.

Pre-flight

Before Phase 0 starts:

  • Create a Supabase account and a dev project.
  • Install the Supabase CLI; sign in.
  • Get an Anthropic API key (used in Phase 5).

Phases

0

Foundation

~2 days

Stand up the Supabase dev project, full schema with RLS and indexes, two real dev Auth users, the Supabase client wired into the Expo app with dev auto-login, and an Edge Function scaffold. No features — just a verified rail with cross-user isolation proven.

1

Events & Market

~3 days

Real users can create, list, search, and view events. MarketScreen renders from Postgres, and ConfirmScreen persists. Manual events first; AI comes later.

2

Fridge customization

~2 days

Each user's personal fridge persists across launches. Drag, rotate, pin, and unpin work, with debounced writes so a flaky network doesn't lose edits. dev2 never sees dev1's fridge.

3

Storage + media safety skeleton

~2 days

Compressed image upload and signed-URL read end-to-end, validated through avatars first. The "only authenticated users can read non-removed media" rule is enforced server-side, not by the client.

4

Public galleries with reports

~3 days

Users upload to event galleries, place sticker overlays, and report content. An admin can remove reported media. Closed-beta default keeps uploads visible immediately; reports are reactive.

5

AI flyer extraction

~3 days

Scan flow returns structured event fields from a real Claude Haiku 4.5 Edge Function. Rate-limited per user per day. ConfirmScreen always allows manual correction; low-confidence fields are highlighted.

6

Production auth + prod project

~3 days

Production Supabase project with Google sign-in. Optional @pfw.edu magic-link verification sets a badge on the profile but never gates writes. Dev auto-login becomes impossible in production builds.

7

Ship gate

~1 day

Final audit before letting any of the 50 invited users in. RLS audit script, storage usage check, updated docs (CLAUDE.md, AGENTS.md), backup posture confirmed, admin runbook written.

Daily loop

Open this doc, read the next phase's overview, hand the model the goal plus relevant existing screens, and let it plan and build the actual steps. Run npm run lint after TypeScript edits. Apply Supabase changes through numbered migration files in supabase/migrations/; never edit the dev database through the dashboard for schema changes.

One rule: Don't go back to polish a previous phase mid-build. Note improvements in a BACKLOG.md and revisit after the ship gate. The MVP isn't done until all seven phases are done.
